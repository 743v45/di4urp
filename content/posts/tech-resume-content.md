很多人花一晚上调简历的字体和配色，只花十分钟填内容。搞反了——技术简历的死活，90% 取决于内容。这篇只讲内容：怎么写、怎么砍、哪些是坑。

## 它同时被三种东西读

| 读者 | 在找什么 | 你该怎么做 |
|---|---|---|
| **ATS 系统** | 关键词匹配 | 技术名词写准写全，`Kubernetes` 别写成 `k8s 也会` |
| **HR / 非技术筛简历的人** | 公司、年限、岗位匹配度 | 大厂名、年限、职级放显眼 |
| **技术面试官** | 你解决过什么难问题、量化成果 | 这是决战区，下面重点讲 |

记住一句话：**没有数字的经历 ≈ 没写。** 这是技术简历和其它简历最大的区别。

## 第一准则：简历是面试的提纲

这一条最容易踩坑，也最致命。

> 你写上去的每一行，都要准备好被面试官深挖 30 分钟。

简历不是"我会什么的清单"，而是 **"我想被问什么的菜单"**——你在主动设置战场。

```
✗ 写「精通 Kubernetes」
  → 面试官：「讲一下 kube-scheduler 的预选/优选算法」
  → 你答不出 → 直接挂，比不写还惨（暴露吹牛）

✓ 写「开发过 K8s operator，处理了 leader election 和
   reconcile loop 的并发冲突」
  → 面试官顺着这个问 → 而你已经准备好聊半小时
```

**推论**：技能区不是罗列你会的，而是**只列你愿意被考的**。半生不熟的技术，要么练到能扛问再写，要么老实写"了解"。

## 经历：黄金公式

每一行 bullet 都该是这样：

> **动词**（做了什么）+ **技术**（用了什么）+ **结果**（量化）

四组 before/after，感受一下差距：

```
① 性能优化
✗ 优化了订单系统的性能
✓ 将订单查询 P99 从 800ms 降到 120ms：加复合索引 + Redis 缓存热点
  + 异步预加载，QPS 提升 3 倍，扛住双十一峰值

② 架构 / 重构
✗ 参与微服务改造
✓ 主导单体应用拆分为 12 个微服务，引入 gRPC + Istio，
  部署频率从每周 1 次 → 每天 3 次，故障恢复从 2h → 15min

③ 业务结果
✗ 负责推荐系统开发
✓ 设计冷启动推荐策略，新用户次日留存 +18%，测算带来约 ¥2000w 年化 GMV

④ 基础设施
✗ 维护 K8s 集群
✓ 搭建 2000+ 节点多集群 K8s 平台，自研调度器将 GPU 利用率
  从 45% 提到 78%，年省机器成本 ¥800w
```

动词换一换，观感立刻不一样：

| 别用（像岗位说明书） | 换成（像主角） |
|---|---|
| 负责 / 参与 / 协助 | 主导 / 推动 / 落地 |
| 做了 / 开发了 | 设计 / 重构 / 从 0 搭建 |
| 优化了 | 将 X 从 A 降到 B / 提升了 N 倍 |
| 帮助团队 | 带领 N 人团队 / 推动全组采用 |

## 项目：写到第三层才有杀伤力

面试官最爱深挖的就是项目。项目描述有三个层级，**L3 是 junior 和 senior 的分水岭**：

| 级别 | 写法 | 效果 |
|---|---|---|
| **L1 流水账** | 用 XX 做了 XX | 像作业，没信息量 |
| **L2 量化** | 用 XX 做了 XX，达到 YY 指标 | 合格，能过筛 |
| **L3 取舍** | 面对约束，对比 A/B 方案，选 A 因为…，结果… | 面试官两眼放光 |

L3 的灵魂是回答 **"为什么选它、为什么不选另一个"**：

```
[场景/约束] → [候选方案 A vs B] → [权衡后选 A，因为…] → [落地结果]

L2:  用 Redis 实现分布式锁，支撑秒杀

L3:  秒杀需分布式锁。对比 Redis(Redlock) vs Zookeeper：已有 Redis 集群、
     对 CP 要求不高（超卖可由库存表乐观锁兜底），选 Redis + Lua 原子脚本，
     单实例 8w QPS。上线后零超卖、无锁失效引发的工单。
```

**一个 L3 项目，比五个 L1 值钱。** 而且它天然扛住"为什么不用 X"的追问——答案已经写在简历里了。

## 量化指标库：找不到数字怎么办

这是大多数人最卡的地方："我就是拧螺丝，哪有什么数字可挂。"其实能挂的维度远比你以为的多：

| 维度 | 可用的指标 |
|---|---|
| **性能** | 延迟（P50/P99/P999）、QPS/TPS、吞吐、响应时间 |
| **规模** | 用户数、数据量、节点数、日请求量、并发连接数 |
| **成本** | 机器成本、人力节省、时间缩短 |
| **质量** | 可用性（几个 9）、故障率、bug 率、MTTR |
| **业务** | GMV、转化率、留存、收入、订单量 |
| **工程效率** | 部署频率、迭代周期、自动化覆盖率、构建时长 |

**真没有现成数据，四个办法：**

1. **量级估算**：知道日活就能推 QPS——`日活 × 人均请求 / 86400`，给出量级（"日均千万级请求"）就比空着强。
2. **用相对值**：降到原来的 1/3、提升 5 倍。相对值有时比绝对值更可信，因为它不依赖公司口径。
3. **去找**：监控面板、季度汇报、年终 PPT、问 leader——这些数字公司里一定有，是你没去捞。
4. **退而求其次写场景规模**：实在没数字，写"服务公司核心交易链路，影响全站下单"也比纯职责强。

## 一份简历投所有岗位，是最大的错

不同技术岗，简历侧重完全不同。投之前对着 JD 调一遍关键词和重心：

| 岗位 | 内容重心 |
|---|---|
| **后端** | 高并发、分布式、稳定性、中间件、性能优化 |
| **前端** | 性能（LCP/INP）、工程化、可视化、兼容性、**作品集链接** |
| **算法 / AI** | 指标（准确率/F1/AUC）、论文、比赛、数据规模、**落地效果** |
| **数据 / BI** | 数据量、链路、建模、对业务决策的影响 |
| **DevOps / SRE** | 稳定性、自动化、**故障复盘案例**、降本 |
| **客户端** | 启动速度、内存、帧率、架构、适配 |
| **安全** | 攻防实战、漏洞挖掘、合规、案例 |

算法岗没有论文/指标、前端没有作品集、SRE 没有故障案例——在这些岗里基本等于没写。

## 技能区：不要进度条

```
✗ Go 90% | Python 80% | Java 70%   ← 面试官根本不信百分比
✓ 语言   Go（精通 · 5y · 高并发后端）、Rust（熟练）、TypeScript（熟练）
  云原生 Kubernetes（精通 · 开发过 operator）、Docker、gRPC、Terraform
  数据   PostgreSQL、Redis、Kafka
```

分级词（精通/熟练/了解）+ 年限 + 用在哪。和经历呼应，别脱节，也别堆砌——三十个名词平铺等于没重点。

## 从合格到抢手：五个杀手锏

下面任何一条都能把你从一堆简历里拎出来：

1. **有 Star 的开源项目**（带链接）—— 10 句自我吹嘘不如一个 1k★ 的 repo
2. **能点的在线 Demo**（带截图/GIF）—— 证明东西真能跑
3. **被转发/收录的技术文章或分享** —— 证明表达力与影响力
4. **极端量化的成果** —— "日处理 20 亿条日志""省 ¥800w"，越具体越难忘
5. **知名背书** —— 大厂经历、给知名开源项目（Kubernetes / Linux / React）提过被合并的 PR

开源贡献单独说一下：给知名项目提 PR 并被合并，和"自己造了个轮子"是两码事，前者权重更高。写法是 `向 Kubernetes 贡献 XX，修复了 YY 问题（PR #123，已合并）`——具体、可验证。

senior 还能加两条：**架构决策的影响面**（影响 N 个团队/系统）、**技术品牌**（社区职务、会议演讲、招聘）。

## 坚决别写

- **照片、年龄、婚育**（除非公司明确要求）
- **无关经历**——社招时的大学社团、十年前的兼职
- **过时技术**——还在写 jQuery / Struts1，会让人觉得你停在原地
- **自我评价**——"热爱学习、踏实肯干、抗压能力强"全是减分项，技术简历直接砍掉
- **薪资期望**——除非 HR 主动问，否则别写在简历上
- **技术名词拼错**——`Kubernetes` 写成 `kubernates`、`Redis` 写成 `Radis`，第一轮就被出局

## 按经验阶段调整侧重

| 阶段 | 重点 | 弱化 |
|---|---|---|
| **应届 / junior** | 项目、基础、学习能力、实习、比赛 | 别硬凑"负责" |
| **mid（3-5y）** | 独立负责的模块、量化成果、技术广度 | 课程项目可以删了 |
| **senior（5y+）** | 架构决策、技术/团队影响力、业务结果、开源品牌 | 教育一行带过 |

## 收尾

技术简历 1 页最佳，最多 2 页，senior 也别超 2 页。投之前对着 JD 把关键词和重心调一遍，维护一份主版本、按岗位 fork。

最后留一句话，它是整篇的纲：

> 简历不是"我会什么的清单"，而是 **"我想被问什么的菜单"**。
