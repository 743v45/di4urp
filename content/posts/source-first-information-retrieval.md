## 一个熟悉的场景

你想看看大家对某个新产品、某首歌、某个事件的评价，于是丢给 AI：

> 帮我找找大家对这个的评价。

AI 很勤快，爬了一圈回来，给你一堆 SEO 农场文、聚合摘要和不知几手的转述。你越读越觉得不对：这些话好像在哪都见过，就是没有一条来自真正用过、听过、经历过的人。

问题不在 AI 笨。问题在指令本身就是「瞎找」——你没有告诉它去哪找。

## 核心命题：信息有原生栖息地

评论不是均匀分布在互联网上的，它们**长在特定的地方**：

- 技术产品的吐槽在 HN、V2EX、GitHub issues
- 音乐的评论在网易云评论区、豆瓣、RateYourMusic
- 游戏的在 Steam、贴吧、NGA
- 实物商品的在电商评论区——尤其是追评和差评

先定位信源，再执行检索。**source-first, search-second**。它的反义词就是把关键词丢进通用搜索引擎，让 AI 在整条信源链里质量最低的那一层（二手聚合）里打捞。

这个行为有几个现成的名字：

- **信源定位**（source-first thinking）：先问「这类信息原生存在于哪里」
- **信息觅食理论**（Information Foraging）：认知科学里的正经理论——人找信息像动物觅食，靠「信息气味」判断哪个「信息斑块」值得去。主动判断气味、直达斑块，而不是在贫瘠的搜索结果里乱翻
- **垂直搜索**（Vertical Search）：与通用搜索相对，去特定领域平台搜特定类型内容
- **信源路由**（source routing）：AI 语境下的叫法——先做一次路由决策，按内容类型映射到正确信源，再定向获取

名字不重要，重要的是：**选对去哪，比怎么搜更重要。**

## 五段流水线

```
① 定位 → ② 获取 → ③ 筛读 → ④ 校准 → ⑤ 维护
 去哪找    怎么拿    怎么读    信不信    怎么持续
```

大多数人只做了前两段的一半，后三段完全空白。一段段说。

### ① 定位：检索前先答三个问题

| 问题 | 回答方式 |
|---|---|
| 这信息**原生栖息**在哪？ | 内容类型 → 平台映射 |
| **谁**会评论这个？他们在哪聚集？ | 想人群，不想关键词 |
| 我要的是**哪种评论**？ | 情绪 / 事实 / 专业判断 |

第三个问题最容易被忽略：不同平台、甚至同一平台的不同排序，提供的是不同类型的评论。**热评 = 情绪共鸣，最新 = 当下状态，长评和追评 = 深度体验。**

比三问更前置的一步：先分清你要的是「事实」还是「观点」。两者的正确信源完全相反——

- 事实（发生了什么）：官方公告、监管文件、原始数据、当事人原文。**不是**媒体报道
- 观点（好不好、怎么看）：原生用户评论、社区讨论。**不是**官方通稿

用媒体观点确认事实、用官方通稿判断口碑，是最高频的信源错配。同一件事往往两类都要，但要分开取，不混着读。

还有一维几乎没人用：**语言**。中英文是两个平行的评论宇宙，技术、学术类英文圈显著更深，国产产品中文圈更真实。换语言关键词重搜一遍，常常直接打开新信源层——这是最便宜、最常被忽略的定位手段。

### ② 获取：到正确的地方，用正确的词

- **用圈内黑话检索**，不用自己的普通话。显卡圈搜「矿卡」不搜「二手有风险」，耳机圈搜「齿音」不搜「高频刺耳」。先潜伏看几条该社区的高赞帖，学它的词汇，再搜
- **穷人版垂直路由**：`site:zhihu.com`、`site:reddit.com`，本质是手动替搜索引擎做信源路由
- **API 优于爬页面**：Reddit 任何 URL 加 `.json` 后缀就是 API，HN 有 Algolia API。结构化数据稳定、可复现，页面改版不影响
- **检索降级为提问**（Ask > Search）：信源地图覆盖不到的长尾问题，最优解不是换关键词，是去正确的社区直接问。提问是主动创造信源

### ③ 筛读：到了评论区，真正的阅读才开始

- **差评优先**：好评信息量低（模板化、从众），差评和追评信息密度最高。先读 1-3 星，再回头看 5 星里有没有「具体细节型」的
- **评分分布比均分重要**：评分天然呈 J 型分布（5 星和 1 星扎堆），均分 4.2 可能是「两极」也可能是「平庸」，分布图一眼看出
- **识别懂行人**：行话、具体参数、横向对比、踩坑细节——一条顶一百条「很好用」
- **水军特征**：无具体细节、发布时间集中爆发、句式雷同、账号无历史
- **利益相关分析**：判断单条评论可信度的第一问不是「说得有没有道理」，是「说这话的人图什么」。首发测评 = 恰饭高发区；竞品社区的贬低帖 = 立场先行；第三方长期用户的追评 = 相对中立
- **幸存者偏差**：你看到的评论是被算法、删评、折叠筛过一遍的。沉默的购买者才是大多数——销量、退货率这类行为数据比评论区诚实

### ④ 校准：每个信源自带滤镜

同一个事件，不同平台是完全不同的评论生态。豆瓣偏文艺批判，HN 反营销见不得 buzzword，知乎爱装，微博情绪浓度最高，Reddit 带英文圈特定倾向。

由此推出三角验证的正确姿势：**「独立」指的是人群不同，不是聚合器不同。** 看三个转载同一微博的公众号不叫三角验证，那是一个信源的回声。豆瓣 + HN + 电商追评，才是真三角。

主动制造三角的第三点：**反向信源**。想买 A 就去看 B 社区怎么骂 A——竞品社区的差评往往是最用力挑毛病的人写的，信息密度反超自家粉丝社区。这是信息茧房的工程化解法。

最后是样本量：评论区是 self-selected 样本，愿意发声的 1% 代表不了沉默的 99%。爆款评论是「最引起共鸣的」，不是「最普遍的」。校准手段：评分人数、退货率、复购行为——**行为数据 > 言论数据**。

### ⑤ 维护：信源是易腐品

- **信源有半衰期**：社区会水化（Eternal September——新手大量涌入稀释原有讨论质量）、论坛会关闭、KOL 会变恰饭。你的信源地图不是资产，是一次性快照，定期校验「这个源最近的输出还靠谱吗」
- **存档意识**：关键评论会删、会编辑、会消失。看到重要评论当场留证：URL + 时间戳 + 截图。不存档的评论，引用时等于不存在
- **雪球法**（snowballing）：找到一个懂行的评论者，翻他的历史发言。**人是移动的高质量信源，比单条评论值钱**
- **知道何时止损**：边际价值定理——在一个信源里翻到「新信息出现率」低于平均水平时就该换地方了。刷评论刷到开始重复 = 该撤了

## 让 AI 替你执行这套思维

关键只有一条：**别给它「找评论」这种模糊指令，给它信源约束。**

```text
找「<产品/事件>」的真实用户评论。
信源约束：
1. 优先去 <垂直平台A> 的讨论区，其次 <平台B>；不要通用网页搜索
2. 中文圈没有结果就换英文关键词搜 <英文社区>
3. 输出前先列出你打算去哪些信源、各取什么，等我确认
4. 每条评论附来源链接和日期；区分热评/最新/追评
```

第 3 条是防瞎找的关键：让 AI 先出**信源计划**再执行，你确认路由对不对，再放它去抓。

更进一步，把「内容类型 → 平台」映射表写进你的 CLAUDE.md 或项目记忆，AI 每次自动路由，不用重复交代：

| 内容类型 | 首选信源 |
|---|---|
| 技术产品 | HN、V2EX、GitHub issues |
| 音乐 | 网易云评论区、豆瓣、RateYourMusic |
| 游戏 | Steam 评测、贴吧、NGA |
| 影视书 | 豆瓣、Letterboxd / Goodreads |
| 实物商品 | 电商追评 + 差评、Chiphell（硬件） |
| 学术 | Google Scholar、arXiv、PubPeer |
| 前沿动态 | Twitter/X、各实验室博客、Papers with Code |

## 收束

一张私域小群里的十句话，常常胜过热搜下的十万条——因为发言成本越高，评论质量越高。

所以下次想让 AI「找找大家的评价」时，先把指令换成：它原生在哪、谁在那里、我要哪一种。**先定位信源，再执行检索。** 剩下的，交给流水线。
